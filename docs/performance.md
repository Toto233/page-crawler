# CPU 性能与省电策略

公司电脑反馈运行后整机明显变慢。项目以真实浏览器的 CPU 降速测试定位开销，首先复现静止时仍不断运行的动画循环，再分别测量计算、SVG 写入和浏览器主线程时间。这里的降速测试不能代替公司电脑上的实际测量。

## 已定位的开销

- 到达鼠标后依然每秒约 60 次求解、绘制，静止页面也持续消耗 CPU。
- 自然款每帧约 525 次 SVG 属性写入；1.6 秒走动样本约 5.2 万次写入，浏览器需要持续处理样式和绘制。
- 赛博款每帧分别绘制 32 条模糊腿影；高 DPI Canvas 和高刷新率屏幕还会放大绘制开销。

## 当前策略

到达鼠标、脚全部收稳且没有粒子、捕食动画时，停止 requestAnimationFrame 循环，保留已画好的蜘蛛。鼠标、滚动、窗口尺寸或行为设置变化会唤醒。暂停与隐藏页面仍停止运行。休眠时间在醒来时计入捕食冷却，不作为一大步移动；需要等待重新捕食的情况只安排一个唤醒定时器。恢复网页时立即重画静止蜘蛛。

正常绘制上限为 30 FPS。最近回调工作耗时的平滑平均值超过 1.8 ms 时降到 20 FPS，超过 5 ms 时降到 15 FPS；低于 0.8 ms 时恢复 30 FPS，避免在临界值反复切换。运动更新最多 60 Hz，显示刷新与动作计时分开，扑跳时长和速度参数保持原值。没有绘制的回调不会求解全部关节；诊断读取会按需求解当前姿态。

SVG 缓存属性值，只写实际变化的值。线宽、透明度与关节半径保留三位小数，关节位置与路径长度保留原有精度。导航文字仅在内容变化时更新。自然款腿影采用细线，赛博款将腿影合并成一次模糊描边。Canvas 像素比上限为 1.25，减少高 DPI 屏幕的缓冲区面积。

三个皮肤保留各自外观、固定三维骨长、追随、滚动、转身与捕食功能。视觉取舍是刷新频率较低、细腿阴影更简单；动作速度参数没有为了省电而调慢。

## 前后测量

2026-10-10，本地 Windows / Edge，1280 × 850 视口，设备像素比 2，CDP CPU 降速 6 倍。测试为空白网页，关闭捕食，分别采样静止和追随鼠标 1.6 秒。下表为该环境的一组前后样本：

| 走动皮肤 | 优化前主线程忙碌比例 | 优化后 |
| --- | ---: | ---: |
| 赛博蜘蛛 | 34.9% | 14.3% |
| 普通幽灵蛛 | 80.4% | 30.6% |
| 斑腹幽灵蛛 | 83.1% | 31.9% |

静止动画回调从约 99 次 / 1.6 秒降到 0，自然款静止 SVG 写入降到 0。优化后静止的总主线程读数仍约 6%–7%，其中包含测试和 CPU profiler 的开销，不能把它算成蜘蛛自身的占用，也不能把上述比例当成 Windows 任务管理器的整机 CPU 百分比。负载、网页内容、浏览器与硬件会改变结果。

运行 `npm run test:performance`。预算要求三种皮肤主线程忙碌比例低于 35%，静止回调不超过 4、SVG 写入不超过 20，运动距离大于 15 像素，避免用停止蜘蛛来通过性能检查。它也包含在 `npm test`，使用 Chromium CDP；在本机其他程序重负载时，应关闭其他测量并单独复查性能结果。报告保存在忽略的 `artifacts/validation/performance-results.json`，包含源码 SHA-256、场景参数和热点采样。

## 在另一台电脑更新

油猴安装文件仍为项目根目录的 `page-crawler.user.js`。替换旧脚本后刷新已经打开的网页，让旧版本的循环退出并重新加载优化版。可在控制面板暂停、继续、移动鼠标和滚动，确认休眠后的唤醒正常。演示页只需刷新。
